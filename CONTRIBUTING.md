# Contributing

Read LICENSE before contributing. Noncommercial use is free; commercial use
requires prior written authorization. Preserve separately licensed MIT examples
and all third-party notices. Contributions must be your own work or submitted
with the necessary rights under the repository's applicable license; raise any
separate contribution terms with maintainers before submitting.

Create a feature branch or fork and open a pull request. Only repository
administrators may merge after required CI passes. Direct pushes, force pushes
and branch deletion on main are prohibited. A code review approval alone does
not grant merge permission. Administrators manage merge access through GitHub
repository permissions and branch rules, not through a client-provided label.

Keep fixes focused and verify the affected Python/TS packaging and Go runtime.
Use synthetic fixtures and generic Agent examples. Do not include private keys,
application credentials, customer data, partner identities or actual integration
and acceptance claims. Jarvis may be used as a hypothetical user-owned Agent.
Use SECURITY.md for private vulnerability reports.

A merge does not authorize changing repository visibility, publishing packages,
replacing versioned release assets or altering the signed stable update channel.
